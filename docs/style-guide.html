1. 基本方針

  • 参考は Supabase のダッシュボード。ライトテーマのみ（ダークモードは別ストーリー。トークンを CSS 変数にしてあるので値の差し替えで足せる）。
  • スタイルは Tailwind CSS v4 の className で書く。色・フォントは index.css の @theme のトークン（bg-surface、text-fg-muted など）を使い、色コードを直書きしない。
  • ボタン・入力欄・カード・バッジ・ダイアログ・メニューは components/ui の部品で描く。同じ見た目を画面ごとに書き直さない。
  • 骨格は 白いヘッダー（48px）＋明るいサイドナビ＋本文。本文の背景は bg、カード・表・パネルは白い surface に 1px の border。影はメニュー・ツールチップ・ダイアログだけに付け、カードには付けない。
  • 色で意味を持たせるのはブランドの緑（主操作・選択中）、danger の赤（削除・エラー）、ステータスの4色だけ。
  • UI の文言は日本語。ボタンは何が起きるかが分かる動詞にする（「変更」「削除」「移動する」）。追加ボタンだけは英語の「New {object}」。

2. 色

名前は @theme の --color-*。Tailwind では bg-{名前} text-{名前} border-{名前} で使い、/30 のように付けると透明度を変えられる（例: ring-brand/30）。

fg-muted — 補助の文字・ラベル・アイコン#707070

サイドナビの選択中（トークン外）#ededed

スマホ表示（lib/useIsMobile.ts）

画面幅 768px 未満（Tailwind の md 未満）をスマホ表示にする。タブレット以上は PC 表示のまま。独自のブレークポイントは足さない。

決まり内容
切り替えの書き方大きさ・表示／非表示・並びの向きなど CSS で済むものは、スマホを基本に書いて md: で PC の値を足す（例: w-full md:w-[420px]）。描く部品そのものが違うところ（サイドナビ ↔ 下部タブバー、横並びの詳細パネル ↔ 全画面シート）だけ useIsMobile() で描き分ける
判定の値useIsMobile() は matchMedia("(max-width: 767.98px)")（MOBILE_QUERY）。幅が 768px をまたぐと再描画される
タップ領域スマホで押すボタン・リンク・タブは 40px 角以上（size-10 / h-10）。見た目を小さくするときも、押せる範囲は余白で 40px を取る
入力欄の文字スマホでは 16px 以上（text-base md:text-[13px] など）。16px 未満だと iOS Safari がフォーカス時に自動でズームする
端末の余白index.html の viewport に viewport-fit=cover を付けている。画面の下端・上端に固定する部品（下部タブバーなど）は env(safe-area-inset-bottom) などの余白を足し、ホームインジケーターと重ねない
 
const isMobile = useIsMobile();
return isMobile ? <BottomTabBar /> : <Sidebar />;

アイコン・ボタン・バッジの使い分け

同じ操作は、どの画面でも同じアイコン・同じ形のボタンで出す。アイコンは web/src/components/Icons.tsx、ボタンは components/ui/Button.tsx の Button / IconButton、バッジは components/ui/Badge.tsx と components/IdBadge.tsx を使う。

6. 書き方の決まり

  • スタイルは Tailwind の className で書く。inline の style に残すのは、ドラッグで決まる幅・ガントのバーの位置など実行時に計算する値だけ。
  • 色は @theme のトークンのクラス（bg-surface、border-border、text-fg-muted）で書き、#xxxxxx を直書きしない。inline style で色が要るときは var(--color-*)（ステータスは STATUS_COLOR）を使う。トークンを増やすときは index.css とこのページの両方を直す。
  • クラスの結合は lib/cn.ts の cn()（cn("a", isActive && "b")）。clsx などの依存は足さない。
  • 部品の見た目を画面側で上書きしない。幅・余白・配置（w-60、ml-auto など）だけを className で渡す。部品に無い見た目が要るなら、部品に variant を足す。
  • hover・フォーカス・無効は Tailwind の hover: focus-visible: disabled: で書く（useState で切り替えない）。
  • Tailwind がソースからクラス名を拾えるよう、クラス名は文字列を組み立てずに全文で書く（`bg-status-${s}-bg` は不可。STATUS_CLASS を使う）。
  • 部品を使わずに素の <button> を置くときは、部品と同じく m-0 border-0 bg-transparent font-sans から始め、ブラウザ既定の見た目を残さない。
  • 破壊的な操作（削除・ステータス変更・移動）は必ず ConfirmDialog を挟む。文面は「対象」と「起きること」を書く。
  • フォームは Enter で送信（IME 変換中は無視: e.nativeEvent.isComposing）、Escape でキャンセル。失敗したらダイアログは閉じない。
  • 表示の好み（列幅、開閉状態）は localStorage に保存し、読み書きは try/catch で囲む。
  • 日付は toLocaleString("ja-JP")。値が無いときは「-」か「説明なし」で埋め、空欄にしない。
  • 読み込み中は「読み込み中…」、空のときは次の一手を書く（例:「ストーリーがありません。「New Story」から登録してください。」）。
